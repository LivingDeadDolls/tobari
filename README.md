# Tobari

AIに任せた仕事の「何をしているセッションか」「終わったか」「結局どうなったか」を確認する、個人向けダッシュボードです。Codex / Claude CodeのCLIを使います。Tobari自身はLLMを動かさず、APIキーやモデル契約も不要です。

## サーバーを起動する

必要なのは **Node.js 22.13以上** と、このリポジトリのcloneだけです。サーバーのための `npm install` やビルド、Docker、クラウド契約は不要です。

Windowsでは **`start.bat` をダブルクリック**してください。

- 起動したウィンドウは閉じません。URL・DB保存先・30秒ごとの稼働ログを表示します。
- 起動中はタイトルが `Tobari - RUNNING`、停止後は `STOPPED` になります。
- 起動失敗・通常の停止後も `pause` で待機し、ログを読めます。
- `Ctrl+C` で停止します。Windowsがバッチ終了確認を出した場合、終了を選ぶとそのバッチは終了します。ウィンドウを直接閉じてもサーバーは停止します。

同じPCでは <http://localhost:3000/> を開きます。初回に生成される **`.tobari/access-key.txt`** をメモ帳で開き、画面にキーを入力してください。サーバー再起動後は再ログインが必要です。

別PCからも使う場合、コマンドプロンプトでサーバー自身のLAN側IPを指定します。

```bat
start.bat --host 192.168.0.174
```

この例では <http://192.168.0.174:3000/> を開きます。IPは環境に合わせて変更してください。Windows Firewallで必要ならプライベートネットワークからのTCP 3000接続を許可します。Tobariがファイアウォールを自動変更することはありません。

Linux / macOSでは同じサーバーを次のコマンドで起動できます。

```bash
npm start
# LANから利用する場合
npm start -- --host 192.168.0.174
```

`--port 3001`、`--db /path/to/local.sqlite`、`--token-file /path/to/key.txt` も指定できます。`--host 0.0.0.0` は全IPv4インターフェースで待ち受けます。既定はループバックのみです。

## CLIを接続する（実行するPCごとに初回のみ）

サーバーとCLIは同じPCでも、Windowsサーバー＋別PC / WSLの組み合わせでも使えます。CLIを動かす環境にもNode.jsとTobariのcloneが必要です。WindowsネイティブCLIではGit for Windows（Git Bash）も必要です。

そのTobariフォルダーで実行します。

```bash
npm link --omit=dev
tobari connect --server http://192.168.0.174:3000
```

同じPCならURLを `http://localhost:3000` に変更します。対話入力でサーバーのアクセスキーを貼り付けます。キーをコマンド引数・コピー用コマンドに含めません。接続情報と送信待ちDBはCLI側のユーザーフォルダー配下 `.tobari/` に保存されます。別設定は `--config /path/client.json` で指定できます。グローバル登録ができない環境では `node /path/to/tobari/src/cli.mjs` を `tobari` の代わりに使用できます。

Codex / Claude Code本体は別途公式の手順でインストール・ログインしておいてください。通常のモデル利用料と実行許可は対象CLI側のものです。

## 普段の使い方

1. ダッシュボードの「タスク登録」で、タイトル・依頼内容・**CLI側PCの作業フォルダー**・任意の関連リンクを登録します。
2. Codex / Claude Codeを選び、表示された起動コマンドをターミナルで実行します。
3. CLIで依頼を進めます。登録した依頼はhook経由で渡します。最初の入力で「登録された依頼を進めて」などと指示してください。
4. hookがセッションを紐づけ、AIの明示的な進捗報告がダッシュボードに戻ります。追加指示・判断・レビューはCLIで行います。

**Codexの初回は `/hooks` でTobariのhookをレビューして信頼してください。** 起動時にスキップされた場合は、信頼後に新しい会話を開始してください。信頼確認を回避するフラグは使いません。hook定義はタスクごとに変わらず、起動情報は環境変数で渡します。clone先やNodeのパスが変わった場合は再確認が必要です。

追加のskillやpluginは必須ではありません。ラッパーがその起動にだけhookと報告手順を渡します。ユーザーの通常の設定ファイルには書き込みません。CLIのhook信頼記録は各CLIが保存します。

## 見えるもの

- タスクの進捗・結論・判断根拠・確認結果・残件・人への依頼
- 主セッションと分担の関係、担当ごとの報告、実セッションID
- 観測イベントのタイムライン、最近の変化、報告日時
- 登録した関連リンク（Issue / PRなどのURL。自動同期ではありません）

`Stop` や子エージェントの終了だけでタスクを完了にしません。取りまとめ役の明示的な完了報告が必要です。30秒以上観測のない稼働表示は「観測途絶」とし、今も動いているとは断言しません。

「動作デモ」はブラウザ内だけの架空データです。再生・停止・シークで動きを確認でき、実DBには混ぜません。

## 切断・停止・バックアップ

CLI側は先にローカルDBへ記録し、サーバーへ送信します。hookは通信失敗で作業を止めません。起動ラッパーが動いている間は定期再送し、停止後に残った報告は接続復旧後に次で送れます。

```bash
tobari doctor
tobari sync
```

新規タスクのリモート起動にはサーバー接続が必要です。再送の履歴は**サーバーが受信した時刻**で表示するため、オフライン中の実際の稼働時間を復元するものではありません。

サーバーを停止し、clone内の `.tobari/` 全体を別の安全な場所へコピーすればバックアップできます。CLIの未送信記録も保護する場合はCLI側ユーザーフォルダーの `.tobari/` も対象です。更新はサーバー停止 → `git pull --ff-only` → `start.bat`。DB・キーはGit管理対象外です。

## 適用範囲と制約

- 個人用・信頼できるLAN向けの0.1版です。HTTPは暗号化されません。インターネットへ直接公開しないでください。安全性が必要な経路ではSSH転送などを使ってください。
- アクセスキー保持者は全タスクの閲覧・登録・報告ができます。複数ユーザーの権限分離はありません。キーの失効は停止中にキーファイルを別名へ移動し、再起動して再接続します。
- プロンプト、ツール引数・出力、最終回答全文は収集しません。ただし登録依頼とAIが明示報告した内容は保存されます。
- Agent Teamsのイベントと所属は観測できる範囲で表示します。実チームの全メンバー追跡・ID対応は未検証です。不明な所属を確定した親子関係として描きません。
- タスクの切り替え、セッション再開の完全な引き継ぎ、Webからの編集・削除、Issue/PR自動連携は未実装です。再起動コマンドは新しい起動として記録し、過去の履歴を残します。
- サンドボックスでローカルDB書き込みが拒否された場合は報告できません。必要なファイルアクセスはCLI側で確認してください。
- WindowsでのhookコマンドはGit Bash向けです。サーバーとCLIのクロスプラットフォーム試験はCIに含めていますが、実CLIのWindows対話セッション・全ターミナルのタイトル動作は別途実機確認が必要です。

## 開発・検証

```bash
npm ci
npm test
npm run test:ui
```

UIテストは専用ポート3100と専用DBを使用します。Linuxの既定ブラウザは `/usr/bin/google-chrome`。`CHROME_PATH` で変更できます。Windows / macOSでは `npx playwright install chromium` を実行してください。

既存のローカルDB直結プロトタイプも `tobari start --db /path/local.sqlite --task ID --title TITLE --provider codex` で利用できます。`--prepare` はCLIを起動せず起動引数・hook・必要な環境変数を表示しますが、起動予定レコードは作成します。
