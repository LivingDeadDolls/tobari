# ローカル試作の検証結果

実施日: 2026-09-20（JST）。DBの時刻はUTCで保存。

## 実装した範囲

`src/cli.mjs` に起動・hook受信・報告・JSON表示を、`src/store.mjs` にSQLite保存と状態の集約を実装。CLI設定は起動引数で渡し、ユーザーの通常の設定ファイルは編集しない。

ローカルDBはイベントと報告を保持する受信先であり、クラウド用送信キューではない。進捗は報告者ごとのリビジョンで更新し、古い報告や子の完了で全体を上書きしない。

## 自動検証

`npm test` で以下を検証。各CLI形式の入力は疑似イベントであり、実モデルや実サブエージェントによる実行ではない。

- 両形式の起動準備→主セッション登録→中間活動→子の開始・終了→明示報告→状態取得。
- 応答終了、子の完了、Claude内部タスク完了では全体を完了にしない。
- 古い報告、同じ報告の再送、同一リビジョンの矛盾を処理。
- 必須報告項目不足、未知の報告者、異なるタスクへの無断再紐づけを拒否。
- プロンプト、コマンド・ツール出力、最終回答のサンプル文字列がDBに残らない。
- 8個のhookプロセスが同時登録しても全ての子が保存される。

`npm run demo` では、疑似イベントを受信CLIへ渡し、`in_progress → 応答終了でもin_progress → 明示報告でcompleted` を確認。

## 実CLIによる確認

| 対象 | 確認できたこと | 未確認・制約 |
| --- | --- | --- |
| Codex 0.155.1 | 対話CLIでhookを信頼後、SessionStart、UserPromptSubmit、Pre/PostToolUse、2件の報告、Stopを保存。AI自身が報告コマンドを実行しタスクがcompletedになった | 実サブエージェント、許可待ち、障害復旧、継続的な再開は未検証 |
| Claude Code 2.1.276 | 起動引数のhookを読み込み、SessionStartからセッションIDを取得。別の起動ではSessionEndも保存 | 実行環境が未ログインで、AIによる報告は検証できず |

Codexの保存結果はタスク `smoke-codex-interactive`。一言は「スモークテストのレポート送信が完了しました。」、revisionは2、根拠は報告送信の確認のみ。プロダクトの機能テストが完了したという意味ではない。

Codexは最初の非対話実行でhookを発火せず、対話UIにて試作が生成した10個のhookが未信頼であることを確認。表示された定義を確認して信頼を追加し、新しい会話で実際の発火を確認した。通常の設定ファイル・認証設定は変更していないが、この試作のhook信頼記録はCodexに追加した。

Claudeの最初の試行では可変長オプションがプロンプトを吸収したため、CLIの引数区切りを修正して再実行。その後はログイン不足により終了した。認証情報は読んだり変更したりしていない。
