# ダッシュボードの再設計

2026-09-20。前版は星を並べた一覧に留まり、関係・時間・判断待ちを読み取れなかった。今回は情報設計から再構成し、実ブラウザで表示と操作を検証した。

## 調査した参考

- [Langfuse Agent Graphs](https://langfuse.com/docs/observability/features/agent-graphs)：実行主体の関係をグラフで見せる考え方。公式ページと掲載されたUIをブラウザで確認。Tobariではタスク→主セッション→分担先を表示し、選択を結果欄に連動させる。
- [LangSmith Observability](https://www.langchain.com/langsmith/observability)：実行の経路と時間的な活動を確認する観点。Tobariでは担当別の観測区間と報告マーカーを同じ時間軸に並べる。
- [Linear Project Overview](https://linear.app/docs/project-overview)：概要・状態・詳細の階層とサイドパネル。公式ページと掲載UIをブラウザで確認。Tobariでは短い到達点を一覧に、根拠・残件・人への依頼を詳細欄に分ける。

参考製品の自動完了判定や内部データ構造をそのまま採用するものではない。Tobariの完了は取りまとめ役の明示報告に基づく。

Plugin Managementスキルを使ってデザイン支援を探索。Figma等は未接続で、ローカルのスキル一覧にも今回の実装に適したフロントエンドデザインスキルは確認できなかった。アカウント接続や外部公開を前提にせず、公式資料を参照し、ローカルのHTML/CSS/SVGとPlaywrightで実装・検証した。Figmaや未導入のデザインスキルを利用したとは主張しない。

## 画面で答えること

| 問い | 表示 |
| --- | --- |
| 今、何を判断すればいい？ | 判断・対応待ち件数と上部の通知帯。選択すると依頼と根拠へ |
| このセッションは何の担当？ | タスク一覧と、担当ノードを選択できる関係図 |
| 結局終わった？ | タスクの状態、担当ごとの報告、結論、残件 |
| いつ進み、どこで止まった？ | 担当別の観測区間、時刻目盛り、過去の報告マーカー |
| 何が変わった？ | 最新の活動フィード、受信時のハイライト、接続・最終観測表示 |

## 動きとデータの意味

- 稼働を最近観測した線だけを動かす。30秒以上観測が途絶えた稼働は、その旨を表示する。この閾値は試作の表示規則で、実際の停止の証明ではない。
- タイムラインはhook観測に基づく推定区間。長い無通知区間は斜線で未観測と表示し、LLM計算時間と混同しない。
- 親セッションの対応が取れる分担は実線。同じタスクへの所属しか分からない場合は点線。名前や関係を補って断定しない。
- 実データに活動がなければ、架空の動きを足さない。「動作デモ」でのみ架空の4タスクを再生する。デモはブラウザ内で生成しDBを書き換えない。
- reduced-motion設定では線のアニメーションを止め、デモも一時停止状態から始める。

## 検証

Chromeで実データ画面、デモ画面、390px幅のモバイル画面を撮影して目視確認。

`npm run test:ui` の5件が成功：

1. 実データ／デモ分離、担当ノード→結果、全体結果へ戻る操作。
2. 検索、状態絞り込み、判断待ちからの選択の連動。
3. 再生／シークによる状態変化、関係図の動き、過去の報告の表示。
4. モバイルのページ幅とreduced-motionへの対応。
5. API通信断の表示、復旧、新しい報告の反映。

この検証で星のクリック領域の不足が見つかったため、SVGの明示的なヒット領域を追加し、強制クリックを使わずに再検証した。

既存のCLI・記録処理と、長い観測欠落を稼働時間にしないテストを含む `npm test` の5件も成功。クラウド、画面からの登録、実Agent Teamsの網羅的な追跡は未実装のまま。
